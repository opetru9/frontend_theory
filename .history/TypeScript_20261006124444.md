# Enum
* se foloseste cind stim sigur o lista de valori care nu se va schimba in viitor si vrem sa asiguram utilizarea lor 
* enum ServerOption {
    APP (= 0),
    DO (= 1),
    OVH (= 2)
  }; daca nu punem valori explicit , automat se ataseaza numere 

  enum ServerOption {
    APP = "APP",
    DO = "DO",
    OVH = "OVH"
  }; -> punem valori daca ulterior vom folosi record unde se vor folosi vaolile la fiecare key 


4. Record: ne permite sa avem o sintaxa mai scurta sa nu copiem text in plus :
* Record<K, V> - un tip generic, cu 2 "sloturi": primul (K) = tipul CHEILOR, al doilea (V) = tipul VALORILOR. Construiește: "obiect unde orice cheie e de tip K, orice valoare e de tip V".
Record<string, string> → K=string, V=string → "obiect cu chei text, valori text".

type ServerOption = "APP" | "DO" | "OVH";
Record<ServerOption, string> === { APP: string; DO: string; OVH: string }

* Readonly<...>

# "noUncheckedIndexedAccess": true

if (!card) {

} ---> asta asigura ts ca daca i e undefined bucla continua si dispare problema

# any 
"oprește complet verificarea de tipuri pentru asta" — poți face orice cu o valoare any (orice proprietate, orice metodă), TS nu se plânge niciodată, chiar dacă e greșit. Foarte nesigur.

# unknown 
"nu știu încă ce e asta" — dar, spre deosebire de any, nu ai voie să faci nimic cu ea până nu dovedești ce e (cu instanceof, typeof, etc.). E "necunoscut, dar protejat".
