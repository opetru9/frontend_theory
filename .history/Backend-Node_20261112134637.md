###### CORS Cross-Origin Resource Sharing
* Mecanism de securitate al BROWSER-ului - decide dacă JS-ul tău poate CITI răspunsul de la un alt origin (domeniu/port/protocol diferit).
* Se configurează DOAR în backend, prin header-e pe răspuns. Backend-ul "permite", browser-ul "verifică și blochează/lasă".
* Header cheie: Access-Control-Allow-Origin: <origine permisă sau *>

# Preflight - 2 tipuri de cereri

1. Cerere simplă → fără preflight, pleacă direct:
- metodă GET/HEAD/POST
- Content-Type: text/plain / multipart/form-data / x-www-form-urlencoded
- fără header-e custom

2. Cerere non-simplă → browser trimite întâi OPTIONS (preflight), abia apoi cererea reală:
- orice altă metodă (PUT, DELETE, PATCH...)
- Content-Type: application/json 
- orice header custom (Authorization etc.)

### Live Data Transfering
When we need data in real time withou any reload of the ui page( chats, navigation apps )

1. Long Pooling (deprecated)- when we send a req and the conection are live since we get any response , then conection closes and cliet send other req waiting for next res , if no data recived in some timeout , req send again.

2. SSE - client open one single conextion during it the server will send new data in one direction only so its not good for chats , or navigation , the clietn dont send anything , just server send the data .

* Server side:
const clients = new Set();

export function SSEfexample(req, res) {

  res.writeHead(200, {
    'Content-Type': 'text/event-stream',
    'Cache-Control': 'no-cache',
    Connection: 'keep-alive',
    'X-Accel-Buffering': 'no', -> tell ngix to not acumulate data but leave each separate info to pass separatly
  });

  res.write('retry: 2000\n\n'); -> retry e un cimp special la sse zice ca daca se rupe conexiunea fa retry dupa 2 sec

  clients.add(res);

  const ping = setInterval(() => res.write(': ping\n\n'), 25_000); -> ':..' in SSE is a comment , we as client cant see it "keep the session alive" , beacuse some tech like proxy or anitivirus can close the conection if no data arrive for too much time 

  req.on('close', () => { -> when current conexion is closed - do this :
    clearInterval(ping); -> stop the setInterval
    clients.delete(res); -> delete all data about last session
  });
}

function newClient() {

}
