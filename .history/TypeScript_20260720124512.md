# Enum
* se foloseste cind stim sigur o lista de valori care nu se va schimba in viitor si vrem sa asiguram utilizarea lor 
* enum ServerOption {
    APP (= 0),
    DO (= 1),
    OVH (= 2)
  }; daca nu punem valori explicit , automat se ataseaza numere 

  enum ServerOption {
    APP = "APP",
    DO = "DO",
    OVH = "OVH"
  }; -> punem valori daca ulterior vom folosi record unde se vor folosi vaolile la fiecare key 


4. Record: ne permite sa avem o sintaxa mai scurta sa nu copiem text in plus :
type ServerOption = "APP" | "DO" | "OVH";
Record<ServerOption, string> === { APP: string; DO: string; OVH: string }

# Readonly
readonly protejează proprietățile individuale ale obiectului. Deci pe scurt: const = variabila nu se schimbă, readonly = proprietățile nu se schimbă, iar const serverDomains: Readonly<Record<ServerOption, string>> le are pe amândouă. 
* Readonly<...> 
* interface Foo {
  readonly x: string;
}

# Type objects
* declaram explicit fiecare key posibila al obiectului chiar daca conditionala '?' astfel ts stie ca acestea vor fi keys folosite
type AdEntry = {
  avatarSrc?: string;
  profileHref?: string;
  profileName?: string;
};
* apoi putem folosi acest type de object pentru orice objects noi 
const entry: AdEntry = {}
** in js file acesta nu se compileaa de catre tsc , ca sa avem asa obiect si in js trebuie enum 

# "noUncheckedIndexedAccess": true
* acesta e din ts config , face ca orice acces la un array prin index (cards[i]) să fie tratat ca posibil undefined — pentru că TS nu poate garanta static că indexul e mereu în limitele array-ului
** Solution: 
if (!card) {
  console.error(`Card ${i} is undefined. Skipping.`);
  continue; - dute la urmatoarea iteratie i++
} ---> asta asigura ts ca daca i e undefined bucla continua si dispare problema
